# Промпты для Claude — по одному на прототип

Копируешь блок целиком, вставляешь в Claude, получаешь **работающий прототип**, не
анимацию. Дальше мы его дорабатываем и ставим на сайт в «Работы».

**Разница, из-за которой всё переделывается.** Демо, которое я построил, было
театром: нажал кнопку — проигралась заранее записанная сценка. Настоящий прототип
держит удар, когда клиент на встрече нажимает не туда, куда мы рассчитывали:
вводит своё, ломает порядок, добавляет строку, перезагружает страницу. Каждый
промпт ниже требует именно этого.

---

## Общая часть — вставляется в КАЖДЫЙ промпт

```
Собери работающий прототип, а не демонстрационную анимацию. Ключевое правило:
всё должно реально работать на настоящих данных, которые вводит пользователь.
Никаких заранее записанных сценариев, никаких «нажми кнопку — проиграется ролик».
Если я введу свои цифры, изменю строку, удалю запись или перезагружу страницу —
инструмент должен вести себя правильно.

Технически:
- Один самодостаточный HTML-файл: HTML + CSS + JS внутри, без библиотек и внешних
  запросов. Шрифт system-ui.
- Данные живут в localStorage, чтобы после перезагрузки всё осталось на месте.
- Есть импорт/экспорт JSON — чтобы можно было унести данные и вернуть.
- Работает на телефоне 375px и на десктопе.
- Валидация ввода настоящая: пустые поля, кривые числа, дубликаты — с понятным
  сообщением по-русски. Молча проглатывать ошибку нельзя.

Оформление (тёмная тема нашего сайта):
- фон #0e202d, текст #F2F7F5, приглушённый текст rgba(242,247,245,.72),
  акцент #7FD8FF, тревожный #ff6b5e, панели #132937,
  границы 1px rgba(242,247,245,.13), скругления 12–20px.
- Интерфейс на русском. Никаких эмодзи — только линейные SVG-иконки, если нужны.
- Сверху узкая шапка: слева «Solutions101 · прототип», справа ссылка «← на сайт».
```

## 1. Сборщик прайсов

```
[вставить общую часть]

Инструмент: сводит прайс-листы поставщиков в одну таблицу и показывает лучшую цену.

Что должно работать по-настоящему:
- Загрузка файла: пользователь перетаскивает CSV (и вставляет текст из буфера).
  Парсер сам определяет разделитель (, ; таб) и кодировку, показывает первые
  строки и даёт назначить колонки: наименование, цена, единица, количество.
- Несколько поставщиков: каждый загруженный файл становится источником с именем,
  их можно добавлять и удалять.
- Сведение: позиции с похожими названиями объединяются в одну строку. Сравнение
  делай по нормализованному названию (нижний регистр, убрать пробелы/знаки,
  «лист г/к 3мм» = «Лист ГК 3 мм») + порог схожести; спорные пары показывай
  пользователю и давай подтвердить или разделить вручную.
- Итоговая таблица: позиция, цена каждого поставщика, лучшая цена подсвечена,
  отклонение от средней, кто дешевле.
- Сортировка и поиск по таблице, экспорт результата в CSV.
- Пустое состояние: понятный экран «загрузите первый прайс» с примером формата.

Дай также кнопку «Загрузить пример» с тремя маленькими встроенными CSV, чтобы
можно было показать инструмент без своих файлов — но это именно пример данных,
проходящий через тот же настоящий парсер.
```

## 2. Бот-калькулятор

```
[вставить общую часть]

Инструмент: считает стоимость по прайсу компании и собирает заявку. Прототип —
веб-версия того, что потом живёт в Telegram.

Что должно работать по-настоящему:
- Редактор прайса: таблица позиций (наименование, единица, цена, минимальный
  заказ), строки добавляются, редактируются и удаляются, всё сохраняется.
- Правила: доставка (фиксированная / от суммы бесплатно / по зонам), скидка от
  объёма (пороги задаёт пользователь), НДС вкл/выкл.
- Окно диалога: пользователь пишет запрос обычным текстом, например
  «40 м² профлиста и 200 саморезов с доставкой». Разбирай текст сам: находи
  количества, единицы и позиции по прайсу (учитывай склонения и сокращения),
  считай по правилам и отвечай развёрнутой сметой строкой за строкой.
- Если позиция не найдена или запрос непонятен — честно скажи, что не понял, и
  предложи выбрать из списка. Не выдумывай цену.
- Из посчитанной сметы — кнопка «Оформить заявку»: заявка попадает в список
  заявок с номером, временем и составом; список виден на отдельной вкладке и
  экспортируется.

Проверь на запросах, которых я не предусмотрел: с опечатками, без единиц,
с двумя позициями в одной фразе, с количеством ниже минимального заказа.
```

## 3. CRM логиста

```
[вставить общую часть]

Инструмент: CRM под перевозки. Настоящая, с данными, а не доска с картинками.

Что должно работать по-настоящему:
- Сделки: создание, редактирование, удаление. Поля: маршрут (откуда/куда), груз,
  вес, ставка, клиент, перевозчик, срок, статус, комментарии.
- Этапы настраиваются пользователем: можно переименовать, добавить и удалить
  колонку. Перетаскивание сделок между этапами с сохранением.
- Карточка сделки открывается целиком: история изменений (кто и когда двинул),
  заметки, файлы (через FileReader, хранить как data URL в пределах разумного).
- Фильтры и поиск: по клиенту, статусу, сроку; отдельно «просроченные».
- Сводка сверху считается из настоящих данных: сколько сделок, сумма в работе,
  сколько просрочено — пересчитывается при любом изменении.
- Экспорт всех сделок в CSV, импорт обратно.

Никаких заранее заложенных «событий». Всё, что видно на экране, должно быть
следствием того, что в базе.
```

## 4. Утренний отчёт владельцу

```
[вставить общую часть]

Инструмент: собирает ежедневную сводку по бизнесу из данных, которые в него
загрузили, и показывает её так, как она придёт в Telegram.

Что должно работать по-настоящему:
- Загрузка данных: CSV продаж (дата, сумма, клиент) и CSV расходов, либо ручной
  ввод операций. Всё сохраняется.
- Настройка показателей: пользователь сам выбирает, что попадёт в отчёт
  (выручка за вчера, план и % выполнения, касса, дебиторка, топ-клиенты,
  просрочки) и задаёт пороги, при которых строка становится тревожной.
- Отчёт считается из загруженных данных на выбранную дату — можно листать дни
  и видеть разные числа. Никаких зашитых значений.
- Предпросмотр в виде сообщения мессенджера + кнопка «Скопировать текст».
- Если данных за день нет — так и написать, а не показывать нули как факт.

Сделай так, чтобы я мог загрузить свой CSV на 300 строк и получить осмысленный
отчёт, а не сообщение об ошибке.
```

## 5. Распознаватель накладных

```
[вставить общую часть]

Инструмент: превращает накладную в строки таблицы.

Честное ограничение: настоящее распознавание фото требует сервера, в одном файле
его не сделать. Поэтому прототип работает так:
- Пользователь вставляет ТЕКСТ накладной (из письма, PDF, копипастом) или
  загружает CSV/TXT. Это реальный вход, а не картинка.
- Разбор настоящий: находи строки таблицы в неструктурированном тексте —
  наименование, количество, единица, цена, сумма — даже когда колонки разъехались,
  разделители разные, а числа записаны как «1 200,50».
- Каждой распознанной строке ставь оценку уверенности по понятным признакам
  (нашлись ли все поля, сходится ли количество×цена=сумма). Строки с расхождением
  подсвечивай и давай исправить вручную.
- Итог: таблица позиций, суммы, контроль «итого по документу совпало/не совпало»,
  экспорт в CSV.
- Если сумма строк не сходится с итогом документа — скажи об этом прямо.

Проверь на грязном вводе: лишние пустые строки, склеенные колонки, «шт.» и «шт»,
запятая вместо точки, перенос названия на две строки.
```

## Как мы это ставим на сайт

1. Ты прогоняешь промпт в Claude, смотришь результат, гоняешь его сам — вводишь
   своё, ломаешь, перезагружаешь.
2. Что понравилось — присылаешь мне файл или ссылку.
3. Я привожу к палитре сайта, проверяю валидацию и телефон, кладу в
   `app/public/demo/<имя>/` и делаю карточку в «Работах».

Остальные восемь инструментов из `PROTOTYPES.md` (сторож цен, экран правды,
конвейер документов, предсказатель, витрина из 1С, генератор рассылки, пробив,
пакеты юрфирмы и стройки) — промпты допишу по тому же образцу, когда скажешь,
что первые пять получились как надо. Смысла плодить десять промптов раньше, чем
проверен один, нет.
