# Взаиморасчёты — что обязано пережить рестайл

Источник истины: **ТП Apex Studio, 26.07.2026** —
`~/Downloads/Telegram Desktop/Техническое_предложение_Взаиморасчеты_Apex_Studio.pdf` (14 стр.,
основание — ТЗ 1.0 от 22.07.2026). Ниже — не пересказ ТП, а **приёмочный чеклист рестайла**:
каждый пункт проверяется кликом после смены дизайна. Если пункт не проходит — рестайл не готов.

Демо: `app/public/demo/vzaimoraschety/index.html` — один файл, 1490 строк, **ноль внешних запросов**.

## 0. Жёсткие ограничения (нарушение = переделка)

- [ ] **Ноль внешних запросов.** Никакого CDN, Google Fonts, внешних иконок и чарт-библиотек —
      приложение обязано работать в контуре клиента без интернета (причина записана в шапке файла).
      Проверка: `performance.getEntriesByType('resource')` должен вернуть `[]`.
- [ ] **Один файл.** Иконки — inline SVG (23 шт. в объекте `ICON`), график — inline SVG.
- [ ] **`tabular-nums`** на каждой денежной ячейке, БИН/ИИН, счётчиках и тултипе графика
      (`.num{font-variant-numeric:tabular-nums;white-space:nowrap}`). Без него колонки сумм
      перестают выравниваться — для бухгалтерского отчёта это дефект, а не мелочь.
- [ ] **Десктоп-first.** ТП явно снимает мобильную адаптацию с этапа 1. Таблица держит
      `min-width:980px` внутри `.tblwrap{overflow-x:auto}` — горизонтальный скролл **внутри
      контейнера**, а не резиновая ломающаяся сетка.
- [ ] **Цветовое разделение направления долга** — прямое требование ТП 3.2-C. Палитру менять
      можно, семантику «зелёное = должны нам, красное = должны мы, серое = закрыто» — нельзя.

## 1. Экраны и навигация (порядок обязателен)

- [ ] Покупатели · Поставщики · Сроки долга · Дашборд · Календарь · Настройки
- [ ] «Настройки» рендерятся **только** при `me.role === "admin"` (единственная реализация ролей)
- [ ] Стартовый экран — **Дашборд**, не Покупатели
- [ ] Свёртка сайдбара: ширина через `flex-basis` (`0 0 260px` / `0 0 68px`), продублирована в JS
      константами `SIDEBAR`. У flex-элемента `width` перебивается базисом — свёртка по `width`
      не сработает.

## 3. Отчёт — 10 колонок, заголовки дословно

`(шеврон)` · **Контрагент** · **БИН/ИИН** · **Валюта** · **Дог.** · **Долг (₸)** ·
**Аванс (₸)** · **Итог (₸)** · **Статус** · `(иконка акта)`

- [ ] Сортировка: Контрагент, Долг, Аванс, Итог (по умолчанию Итог ↓)
- [ ] Три KPI пересчитываются **по отфильтрованному набору**: Должны нам · Должны мы · Чистая позиция
- [ ] Фильтры: поиск по названию и БИН/ИИН · организация · чип «Скрыть нулевые» · чип «Только должники»
- [ ] Итоговая строка `tfoot` с пометкой **«(по всем строкам, не только по странице)»** —
      пометку убирать нельзя, это честность итогов при `PAGE_SIZE = 50`
- [ ] **Три уровня раскрытия:** контрагент → договор × счёт (знак вклада, Дт/Кт, курс, сумма
      в валюте) → документы расчётов. Это ТП 2.5 + 3.2-C + 3.6 одновременно.
- [ ] Пустое состояние «Ничего не найдено»

## 4. Расчёт — цифры и счета не трогать

Формулы ТП 2.3, дословно:

```
Покупатели: Итог = (Дт 1210 − Кт 1210) − (Кт 3510 − Дт 3510)
Поставщики: Итог = (Кт 3310 − Дт 3310) − (Дт 1710 − Кт 1710)
```

Свёртка: `актив (1210, 1710) → дт − кт`, `пассив (3310, 3510) → кт − дт`,
`net = Σ sign × folded` по активным правилам.

Правила по умолчанию — пять строк:

| rule_set | Счёт | Знак | Сторона | Активен |
|---|---|---|---|---|
| Покупатели | 1210 | +1 | Долг | вкл |
| Покупатели | 3510 | −1 | Аванс | вкл |
| Покупатели | 3310 | −1 | **Зачёт** | **ВЫКЛ** |
| Поставщики | 3310 | +1 | Долг | вкл |
| Поставщики | 1710 | −1 | Аванс | вкл |

- [ ] Правило «Зачёт» («покупатель = поставщик») остаётся **выключенным по умолчанию** —
      как в выгрузке клиента
- [ ] Aging: `0-30 / 31-60 / 61-90 / 90+`, `OVERDUE_DAYS = 30`, срок считается от даты документа
- [ ] `PAY_TERM_DAYS = 30` для календаря
- [ ] `TODAY = "2026-07-31"`, `OUR_ORG_NAME = ТОО «Тумар Курылыс»`,
      `RATES = {USD:512.34, EUR:551.20, RUB:5.42}`
- [ ] Контрольные суммы (зачёт выкл): должны нам **48 377 725,08** · должны мы **479 737 547,06** ·
      чистая **−431 359 821,98**. После рестайла обязаны совпасть до копейки.
- [ ] Глоссарий счетов в подсказках «?» (1210/3510/3310/1710/1280/3390/2110/4110) — это контракт,
      формулировки не переписывать

## 5. Печать и экспорт

- [ ] **Акт сверки** — самостоятельный HTML в новой вкладке (`buildActHtml` + `window.open`),
      своя кнопка «Печать», `@media print{.noprint{display:none}}`, таблица
      **Дата · Документ · Счёт · Дебет, ₸ · Кредит, ₸**, вывод «Задолженность в пользу …»,
      примечание про данные контрагента, подписи обеих сторон
- [ ] **Печать основного экрана** — `@media print{aside,header,.toolbar,.noprint{display:none}}`.
      Рестайл, который переносит фильтры или заголовок в другой контейнер, **обязан обновить это
      правило**, иначе они полезут в печать.
- [ ] **Экспорт** — `report.csv`, разделитель `;`, UTF-8 BOM (иначе Excel открывает мастером
      импорта). Шапка и три итоговые строки (ИТОГО / в том числе должны нам / в том числе должны
      мы) — часть критерия приёмки, менять нельзя. Экспорт учитывает поиск, чипы, организацию, дату.

## 7. Ловушки, найденные при разборе

- **`toggleDocs` использует неявный глобальный `event`** (строка 1133, `event.stopPropagation()`).
  Перевод на `addEventListener` без передачи события роняет третий уровень раскрытия с TypeError.
  Весь UI на inline-`onclick` со строковой интерполяцией и `esc()` / `JSON.stringify` —
  переходить на делегирование можно только целиком.
- Все `th` имеют `cursor:pointer`, включая пустые и несортируемые — заголовки выглядят
  кликабельными и молча не работают. Рестайл — хороший момент это поправить.

## 8. Известные расхождения демо и ТП (не регресс рестайла, но знать)

| ТП требует | В демо |
|---|---|
| Авторизация логин/пароль, роли admin и user (3.2-B) | Экрана входа нет, `me` захардкожен как admin |
| Журнал обращений к 1С и входов (3.2-B, 3.4) | Отсутствует; признано текстом в подзаголовке Настроек |
| Сортировка **по любой** колонке (3.2-C) | Только 4 из 8 |
| Выгрузка в **Excel** (2.4, критерий №5) | CSV `;`+BOM, не .xlsx |
| Счета 1280/3390/2110/4110 (3.3, вопрос Б-2) | Есть в глоссарии, но валидатор их отклоняет |
| Просроченная задолженность **и лимиты** (2.4) | Просрочка есть, лимитов нет |
| Сходимость с ОСВ, расхождение 0 ₸ (критерии 1–2) | Не проверено — нет базы клиента |

Смысловые баги, которые стоит починить заодно:
- «Сроки долга» на вкладке **Поставщики** оставляет заголовок плитки **«Всего должны нам (₸)»**,
  хотя показывает наш долг поставщикам.
- **Акт сверки игнорирует выбранную дату отчёта** — `buildActHtml` строится на `todayISO()`
  и всегда печатает «по состоянию на сегодня».
- Метка **★** («покупатель = поставщик») есть в данных у 5 контрагентов и в CSS, но **не выводится**
  — понять, к кому относится правило «Зачёт», по интерфейсу нельзя.
